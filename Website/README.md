# Learned Media Website

Live site: [stiwarilbj.github.io/Learned_Media](https://stiwarilbj.github.io/Learned_Media/)

## Launch

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

To build the GitHub Pages version locally, run `npm run build:github-pages`. It writes the static site to `out/`.

## Use

1. Open **Settings**, paste a Gemini API key, and press **Connect Gemini**
2. Select topics and press **Start learning**
3. Use **Learn more** or ask questions on generated fact cards
4. Open **Videos**, add a YouTube Data API v3 key in Settings, and import the approved creator library

No demo facts are included. Facts appear only after Gemini successfully generates them. Keys are remembered in encrypted browser storage and sync privately with your signed-in Google account; the Settings page links directly to [Google AI Studio](https://aistudio.google.com/app/apikey).

On GitHub Pages, Gemini and Wikipedia requests run directly in your browser. API keys are sent to Google for provider requests and to the account-private credential table for sync. They are excluded from workspace snapshots and never committed to GitHub.

The Videos workspace uses the same account-scoped storage for its YouTube key. Settings includes direct links to create a Google Cloud project, enable YouTube Data API v3, and create a restricted API key. The imported catalog is kept in IndexedDB and only approved creators and individually approved videos are used.

While connected, overdue creator sources refresh once a day. Use **Refresh videos** for an immediate scan. 3Blue1Brown is limited to the approved Neural Networks and Statistics playlists, including future additions.

### Private performance diagnostics

Diagnostics keep numeric totals, sample counts, and maxima in memory, with at most 45 fixed service/metric buckets and saturating counters. They also keep a 64-event ring of malformed Wikipedia and YouTube response fingerprints, aggregated by fixed schema paths and observed JSON types. Nothing is persisted, synced, logged, or uploaded. Reloading the website or restarting the Mac app clears them. They contain no keys, account/workspace IDs, URLs, queries, prompts, response values, source text, or error messages. Server rendering does not collect these counters.

In browser developer tools, use `LearnedMediaDiagnostics.snapshot()` and `.reset()`; schema fingerprints are listed in `providerSchemaFailures`. Each worker and Mac frontend has its own runtime counters. In the Mac web inspector, `await __learnedMediaNativeRequest("performanceDiagnostics", {})` reads native transport/cache counters and schema fingerprints; pass `{reset: true}` to clear them. Reading counters sends no network requests.

`requests` counts attempted transport calls, including failures; `retries` counts subsequent model attempts or eligible background retries. `cache_hits`, `cache_misses`, and `coalesced` distinguish completed reuse from shared pending work. `queue_ms` measures admitted work using a monotonic clock. `request_bytes` counts existing JSON bodies; `response_bytes_read` counts bodies already consumed by Gemini/YouTube (and native transports). Native streamed sizes reconstruct line separators and are approximate. `response_bytes_reported` uses Content-Length where exposed, which may reflect compression and is not added to read sizes. Missing headers produce no sample. Requests are never cloned or replayed for measurement; Wikipedia/cloud responses on the website use reported sizes to avoid extra reads or serialization. Cache probes are aggregates, not counts of unique user operations, and diagnostics cover the instrumented transports rather than every browser resource.

### Shared website and Mac data

Run `npm run generate:native` after changing shared sources. It runs every `scripts/build-native-*.mjs` generator, including writer data, topic/video search runtimes, credentials, caching, prompt instructions, units, and evidence policies. Commit the generated JavaScript and Swift files; rebuild the Mac app when its resources change.

`npm run check:native-data` regenerates those files and fails if their bytes differ, including missing outputs. It leaves regenerated files available for inspection. Pull requests run this check, and Pages deployment runs it before building. New generators using the same filename convention are included automatically. Catalogs maintained separately by hand are not generated by this command.

### Incremental search indexes

Website and bundled Mac workers retain unchanged video and topic search entries. Ordinary updates send only added/changed searchable records and removed IDs; ordering IDs are sent only when order changes. Custom-topic records contain names, aliases, and paths, so selection, expansion, and weight changes do not rebuild search metadata. Topic alias edits normalize only the affected entries; structural changes repair ordering and ancestor links without renormalizing the built-in catalog. The yielding topic fallback uses the same incremental engine.

Each update names its base revision. A revision mismatch requests a full initialization and invalidates obsolete searches/results. Workspace imports/restoration, catalog or search-policy changes, and forced YouTube refreshes retain full rebuild paths. Ranking, filters, 100 suggestions, Gemini behavior, and UI are unchanged.

### Conditional downloads

YouTube downloads on the website and Mac retain server ETags (including whole-response JSON ETags) or Last-Modified dates and revalidate exact requests before reuse. A `304 Not Modified` reuses the previously validated body; approval, pagination, and Shorts checks still run. Validators are scoped to the API key, full request, and request origin/referrer, held only in memory, and bounded to 100 entries, 4 MiB, and 24 hours per service. Malformed/error responses, `no-store` responses, and unsupported `Vary` headers are excluded.

Native Wikipedia downloads use the same policy, excluding missing pages so the separate one-minute missing-page cache remains authoritative. Browser Wikipedia Action API requests retain their existing path because its CORS policy restricts conditional headers. Conditional requests can still consume provider quota. See [YouTube ETags](https://developers.google.com/youtube/v3/getting-started#etags) and [MediaWiki CORS headers](https://www.mediawiki.org/wiki/Manual:$wgAllowedCorsHeaders).

### Prompt instructions

`lib/prompts.ts` builds one instruction block per operation, followed by labeled task data. `lib/prompt-instructions.json` is the shared source for connection, card, answer, and search rules. Empty optional fields and identical rules/fields are omitted; evidence and user text retain their exact content. Catalog versions remain in request cache keys rather than model prompts.

After editing shared instructions, run `npm run generate:prompts` to update the native Swift instructions. `npm run test:generation` checks that the generated copy is current and verifies prompt isolation, citations, and request counts.

Run `npm run test:prompts` for the [fixed prompt failure set](scripts/prompt-evaluation/README.md). It reports task success, citation validity, duplicates, response size, and Gemini call count against a committed baseline. Pages CI rejects regressions. Replays use no API key; changed wording requires measured reliability gains rather than treating unchanged mock responses as proof of improvement.

Question answers pass the exact current query first, separately from supporting card context and prior conversation. Question-specific instructions require a direct first-sentence answer, coverage of every requested part, and omission of irrelevant card details. Supplemental evidence can support the answer while remaining distinct from evidence for the card's claim.

Candidate generation sends all seven default slots in one batch, each with a stable ID and assigned topic. Candidates must use different facts and angles; weak or duplicate slots may be omitted rather than padded. The response schema caps candidates at the requested slot count and permits empty batches. Recovery requests only unfinished slots and preserves completed cards.

Card prompts include only the assigned difficulty levels and requested sentence structure. Length limits match validation (exact sentence count, at least eight words and 35–600 characters per sentence). Inactive surprise mode and presentation-only display settings are omitted; difficulty constraints are shared with the native app.

Prompt conflicts follow an explicit content priority: the current question/task, assigned topics and active mode, required format and length, then optional style. Learning answers retain the original question as their target; response schemas, evidence validation, and citations stay mandatory. Connection probes remain minimal.

Standalone cards and question answers use separate compact builders. Cards retain exact sentence counts, topic difficulty, and evidence IDs. Answers use only relevant card context and question evidence, with preferred length that can expand to cover every requested part; card generation settings are excluded from answer context.

Before grounded writing, Wikipedia/catalog evidence is retrieved through the existing local cache and ranked by the intended claim, title, and topic path. Only the strongest complete passage and a sufficiently relevant adjacent passage are sent; heading-only matches and unfinished passages are excluded. Compact source titles and stable content-based evidence IDs preserve local citation restoration without an extra Gemini source-discovery call.

Grounding responses contain sentence indexes and evidence IDs only. Local restoration checks every reference against the current card’s allowlist, restores exact quotation/section/source data, and runs citation validation. Unknown IDs, IDs assigned only to another card, empty ID lists, and out-of-range sentence indexes reject the affected card without discarding completed cards.

Grounding requires `claimEvidenceIds` supporting the specific main claim as well as evidence for each sentence. Subject-only mentions are insufficient. When supplied passages cannot establish the claim, Gemini returns `{slot, status: "needs_evidence", claim, missingEvidence}` without invented card text. Only the unfinished slot is recovered; completed cards remain intact. Claim evidence IDs pass the same local ownership checks as sentence citations.

Shared grounding passages are pooled once per canonical source, normalized section, and normalized passage text. Identity normalization collapses whitespace and canonical Unicode variants while preserving punctuation, numbers, case, and negation. Stable evidence IDs are reused across cards and retries; each card retains its original local quotation and section for citation restoration.

Evidence, supporting cards, prior conversation, and video-verification metadata are serialized as `{kind: "reference_material", data: ...}` fields. The shared prompt builder adds one explicit instruction to ignore commands, role claims, or prompt-like text inside these fields. JSON escaping keeps embedded headings and newlines inside reference data, while preserving exact quotations for local validation. Connection checks and interpretation-only requests do not carry this evidence policy.

Unresolved search interpretation returns one compact concept plan without prose or a query restatement. Case and whitespace variants coalesce into the same cached interpretation. Video groups contain equivalent `terms` and separate optional `related` hints; related matches can break ranking ties but cannot satisfy required concepts. Topic groups retain equivalents and related terms for local catalog ranking. The existing optional uncertain-video verification checks metadata, rather than reinterpreting the query.

YouTube hard filters are owned by local parsing and user selections. Semantic interpretation returns only concept groups and ranking hints; model-supplied channel, date, duration, exclusion, approval, Shorts, or sorting changes are ignored. Eligibility is enforced before local ranking and again after optional metadata verification. Unknown or conflicting explicit channels produce no results; constrained records with missing date or duration metadata are rejected.

Search rankers record matched and missing concept IDs for each result. Ordinary multi-part searches require all concepts. Explicit OR uses complete alternative clauses, including synonyms and evidence spread across title, tags, and description. Topic dropdowns keep partial recommendations below complete meaning matches within each section; partial matches never enter the filtered topic tree. Local AND/OR structure and recognized concepts survive optional enrichment.

Question-answer prompts locally recognize leading “when,” “why,” and “what’s the difference” questions and add only the applicable date/time-first, cause-first, or distinction-first instruction. Original query text is preserved. Unknown patterns use the general answer prompt, and source limitations remain mandatory. Web and native builders use the same instruction text; this adds no Gemini request.

For explicit multi-part questions, the answer prompt also includes a short local coverage checklist. Each item must be answered or identified as unsupported by the evidence. Splitting ignores quotes and parenthetical text, preserves the original query, and falls back to the general prompt when a reliable short checklist cannot be extracted. No separate interpretation request is made.

## Account credentials and sessions

Google OAuth must be enabled in Supabase with redirect URLs for the website and
`learnedmedia://auth/callback` for macOS. The browser SDK persists and refreshes
its own session. Signing out uses the local session scope, so it does not sign
out other devices. Native refreshes are coalesced and their expiry is persisted.

`supabase/account-credentials.sql` creates separate per-account/per-provider
credential rows with owner-only read/insert/update policies. Empty values record
removals. This uses Supabase access controls and infrastructure storage encryption;
it is not end-to-end encryption. Never put keys in OAuth metadata, exports,
workspace snapshots, fact memory, or logs. Browser recovery copies use AES-GCM;
macOS recovery copies use Keychain. Account switching clears active credentials
before restoring the next account. Existing device keys migrate once, with an
existing account copy taking precedence over a legacy import. Explicit offline
edits take precedence and are retried on reconnect/focus.

Run `npm run test:credentials` for the shared web/native sync state machine and
`node scripts/build-native-credentials.mjs` after changing it. The transactional
`supabase/test-account-credentials.sql` verifies owner and anonymous isolation
without retaining its fixture users or keys. Normal runtime sync never requires
service-role credentials.

### Workspace revision protection

Apply `supabase/workspace-sync.sql` for initial setup, followed by
`supabase/workspace-revision-guard.sql` before deploying these clients. The guard
atomically compares each write's `expected_revision_id` with the current workspace
head under a transaction-scoped lock. It also guards legacy direct inserts;
older open clients must reload or update before syncing existing workspaces.

Web and Mac restore workspace heads in pages of at most 100, ordered by the
stable `workspace_id` (not the changing revision UUID). Restoration first captures
the highest visible workspace ID, then uses an exclusive lower cursor and that
fixed inclusive upper bound on every page. No offsets or full snapshot list are
transferred to establish the boundary. New keys beyond the bound wait for the
next restore; concurrent updates to existing heads do not move their keys.
This is a bounded traversal, not a point-in-time snapshot of workspace contents.
Fact-memory loading starts concurrently. All pages must validate before restored
records or observed revision IDs are accepted; cancellation keeps local recovery.
Each workspace snapshot is checked independently. An invalid snapshot is omitted
from the merge so its last valid local copy remains, while valid siblings restore
normally. Only fixed validation categories/counts are recorded locally; rejected
snapshot contents and exception messages are never retained in diagnostics.
Envelope revision identity remains available for safe conditional writes, but
invalid content is never acknowledged or cached as a conflict winner. Broken page
cursors and transport failures still stop the restore rather than accepting an
unverifiable partial traversal. No database migration or new RPC is needed.

Web and Mac remember observed revisions per account/workspace. A conflict reloads
the latest revisions, runs the existing `updatedAt` merge, and retries at most
three attempts. Accepted snapshots retain their deterministic revision IDs so a
lost response can be retried without duplicating or rewinding history. Account
changes cancel stale operations, and unresolved contention retains local recovery
copies. Workspace payloads and the timestamp-based merge policy are unchanged.

Run `npm run test:cloud-revision` and `npm run test:workspace-revision` for client,
native-controller, and revision-identity regressions. Run
`supabase/test-workspace-revision-guard.sql` against a test database to verify the
actual trigger, transactional rollback, account isolation, and idempotent inserts;
its fixtures roll back. `supabase/test-workspace-cursor.sql` also verifies a
1,105-workspace traversal with new keys and revision changes between pages.
Use only isolated fixture IDs, never an existing account.

### Card downloads

Settings → Download Facts offers one PDF (default), one TXT, or individual PDF/TXT files in a ZIP containing one named folder. The device remembers this choice. Download session always captures the entire active feed in its current order, including restored/offscreen cards regardless of search. A card’s More menu offers a single-file download in the chosen format.

Download names capture the activated tags when preparation starts: fully selected parents and descendants qualify, mixed parents do not. Choose up to ten unique names from shallowest to deepest (alphabetically within each depth), then alphabetize the chosen names and join them with commas. Multi-card combined files use this name; ZIPs use it for both the archive and its single enclosing folder. With no active tags, the name is Cards. Filesystem-unsafe characters are sanitized; overlong names discard lower-priority tags before truncating a single remaining name. ZIP entries use `001 - Card title` numbering. Any one-card download is a plain PDF or TXT named after its title, even with a ZIP preference selected; the preference is preserved.


Downloads retain the complete original wording, topic path, Wikipedia links, and image credits. PDF images are prepared from saved URLs with three concurrent downloads and a 12-second timeout; unavailable pictures are reported without losing text. TXT never requests pictures. PDF code and bundled OFL-licensed Noto Sans fonts load on demand. Preparation can be canceled; workspace/account changes discard obsolete jobs. ZIP exports are limited to 512 MiB and use UTF-8 numbered filenames. No Gemini or source-discovery requests are made.

Run `npm run test:exports` for shared naming, snapshot, ZIP, cancellation, and text-only behavior checks.
